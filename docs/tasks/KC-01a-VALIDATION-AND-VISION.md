# KC-01a 검증 보완과 시각 입력 설계

2026-09-17 · status: ready · 사용자 승인: 물리 검증을 먼저 보완하고 시각 입력은 별도 설계한다. Claude가 아래 A를 구현/실험하고 B는 설계한다. 기존 [KC-01a 설계](../design/KC-01a-TORSO-BAT-COORDINATION.md)의 후속이다.

## 현재 판정

KC-01a는 역학 시제품 구현 완료, 협응 우위 검증 미완료다. 기존 비교는 참고 결과이며 dt 비수렴 조건의 순위를 확정하지 않는다. 테스트99개 통과 보고는 물리 수용을 대신하지 않는다.

현재 관측은 공의 정확한 위치/속도와 예측 도착시간을 포함한다. TorsoBatController는 보정된 목표/시점으로 구동하는 oracle이다. fly_pov는 world 고정 촬영 카메라이며 눈 입력이 아니다. RetinaEncoder는 좌표→스파이크 초기 코드로 현 제어기에 연결돼 있지 않다. 현재 실제 시각 인식·신경회로 타격 학습은 미구현이다.

## A. 다음 구현: KC-01a-validation

### A1. 비교 해석 정정 및 기준점

- 기존 결과 파일은 보존하고 비교 보고서 상단에 후속 정정 링크를 남긴다. 점수/일 비율만으로 에너지와 협응 효과가 분리됐다는 결론을 철회한다.
- 조건명은 `arm_swing_with_torso_hold`, `torso_swing_with_arm_hold`처럼 능동 유지 축을 명시한다. 옛 이름과 매핑을 기록한다. 유지 모터의 일도 총 투입량에 포함한다. 진짜 lock을 쓰면 관절 제거/물리 구속으로 별도 모델을 만들고, 매 substep qpos/qvel 강제 초기화로 흉내 내지 않는다.
- 모든 조건에서 같은 모델/질량/재료/초기 상태/투구/보상 버전을 고정한다. 아직 gear 증가·새 타이밍 최적화·재료 재보정은 하지 않는다. 변경 전 설정/소스 해시와 원자료를 저장한다.

### A2. timestep 수렴 — 최우선

- 네 조건 모두 physics_dt=0.00025/0.000125/0.0000625s로 검사, control_dt=0.005s 고정. frame_skip와 시간 관련 파생 설정을 함께 정합적으로 구성한다.
- 두 검사를 분리한다: (1) 기준 control tick별 명령을 저장해 zero-order hold로 같은 물리시각에 재생, (2) 각 dt에서 동일 제어기를 독립 실행. 명령 재생으로 접촉 물리를, 재실행으로 상태 피드백/분기까지 포함한 민감도를 본다.
- 최초 접촉/분리/재접촉/착지 시각, 접촉 지속, 법선·침투·impulse, 배트·공 접촉 전후 속도, 출구속도, 착지 좌표, 점수, 실제 제어 상태 전이를 기록한다. 최초로 결과가 갈라지는 구간을 찾는다.
- 설계 수용치(측정 전 고정): 두 가장 미세한 dt에서 명목 조건별 사건 분류/scoring_valid 동일, 공통 접촉/분리시각 차≤0.5ms, 출구속도 벡터 차≤max(0.1m/s,기준속도×2%), 착지XY/비거리 차≤max(0.05m,기준거리×2%). 미세화 후에도 경계에 걸리면 실패/미확정으로 남긴다. 임계값을 결과에 맞춰 느슨하게 하지 않는다.
- 수렴 실패이면 비교 우위 결론과 시각 정책 통합은 보류한다. 추가 세분화로 원인을 진단할 수 있으나 공/배트 재료나 모터를 몰래 바꾸지 않는다. 변경 필요 시 원인과 최소 수정안을 별도 제시한다.

### A3. 정착 관찰

- 타구 outcome/점수는 기존 착지 시점에 확정한다. 진단 모드에서는 물리 관찰을 제동 시작 후 최소1.2s까지 지속하고 타구 종료 이후 보상·추가 접촉을 원래 outcome에 소급 반영하지 않는다.
- 일반 환경의 terminal 뒤 step 거부 계약은 유지한다. 별도 diagnostic runner/명시적 모드로 구현해 숨은 연장을 피한다.
- 각 축별 제동 시작을 기준으로0.5s 이내 |qvel|<0.2rad/s, 이후0.2s 동안 각도 p-p<0.02rad와 속도 조건을 연속 만족하는지 검사한다. 관찰 시간 부족과 실제 정착 실패를 구분하고 무공 스윙도 확인한다.

### A4. 에너지 검증과 공정한 비교

- 유한한 일 값만으로 에너지 수지가 검증됐다고 부르지 않는다. 먼저 무공에서 Δ(운동+중력위치 에너지), 액추에이터 순 일, 감쇠 손실, 알려진 외력/구속의 일과 잔차를 같은 적분 구간에서 기록한다. 지원하지 않는 항은 명시하고 검증 완료로 표시하지 않는다. timestep 감소에 따른 잔차도 비교한다.
- 총 양의 일 W+=Σ∫max(τ_i*qdot_i,0)dt, 흡수 일, 총 순간 양의 출력, 축별 토크를 측정한다. 제어비용∫u²dt를 joule로 쓰지 않는다. 충돌 전 가속 구간과 충돌 후 감속/정착 구간을 분리한다.
- A2 통과 후에만 공통 사전 지정 W+/총 피크출력/축별 토크 한도 아래 비교한다. 예산은 무공 기준 측정으로 정하고 점수를 보기 전에 config에 고정한다. 한도 도달 시의 제한 정책도 모든 조건에 동일하게 적용한다. 같은 gear나 사후 점수/J 나눗셈은 공통 에너지 예산의 대체가 아니다.
- 제한이 활성화되면 제어 일정도 바뀌므로 새 config로 기록하고 A2의 최종 수렴 확인을 반복한다. 우위가 사라지거나 모든 조건이 실패해도 정상 연구 결과다. 가장 좋은 비거리 후보를 얻기 위한 무제한 탐색은 하지 않는다.

### A5. 시간창과 보고

- 수렴된 설정에서 요청 trigger offset -20~+20ms/1ms 간격 및 실제 가속 시작 tick을 기록한다. 5ms 제어 양자화로 동일하게 실행된 조건은 독립 표본이 아니다. 성공 시간창·점수·incomplete를 보고하고 시차 구동의 offset은 우선 두 축에 동일 이동을 적용해 축간 지연을 보존한다.
- 성공 시간창과 수치 수렴은 별개다. ±5ms 실패가 남으면 그대로 제한을 보고한다. 물리 수렴 전 성공률 최적화로 넘어가지 않는다.
- 산출물: 네 조건×dt 표, 최초 발산 구간 그림, 공통 예산 비교표, 축별 정착표, 에너지 잔차, 명령 일정/설정/원자료, 대표 영상. 기존 B1 회귀·KC 테스트·두 pytest 진입점·전체 lint를 수행한다. 기록은 records/validation에 추가하고 STATUS는 현재 판정만 갱신한다.

## B. 이번에는 설계만: VISION-01

### 입력 계약 초안

- 카메라를 head/eye 프레임에 고정하여 머리 운동을 따라가게 한다. 첫 기준선은 일반 RGB/회색조 영상이며 실제 복안 모델과 구분한다. 좌우 눈 사용 여부/내외부 파라미터/노출·해상도/fps/지연/가림/배경을 구현 전에 명세한다.
- 파이프라인: 눈 영상+capture timestamp → 영상에서 공 위치/이동 추정과 불확실성 → 타격 제어. 관절 각도·속도 등 proprioception과 접촉 센서는 별도 허용 채널로 명시한다.
- 정책 입력 금지: 시뮬레이터 공 XYZ/속도/예측 도착시간/정답 코스/보정된 정답 트리거/info의 숨은 상태. 정답은 evaluator만 사용한다. 미래 프레임/메타데이터/영상 점수 overlay도 입력하지 않는다. 깊이/segmentation을 사용하면 RGB-only와 다른 감각 조건으로 표시한다.
- 영상 갱신과 control/physics clock을 분리하고 최신 관측의 age를 제공한다. 가림/미검출 시 정답 좌표 fallback을 금지한다. 작은 공이 초기 거리에서 몇 pixel인지 측정하고 실제 검출 가능성을 먼저 검증한다.
- 눈 입력이 실제로 사용되는지 가림/영상동결/시간지연 대조를 설계한다. 고정 투구의 시간표만 외운 성공과 구분하기 위해 평가에서는 release 시각 변동 등 진단 조건을 미리 분리한다(이번에 투구 환경을 확장 구현하지 않음).
- 단계: 녹화된 눈 영상으로 가시성·추정 평가 → 수렴한 물리에서 고전 영상 기반 폐루프 기준선 → 스파이크 encoder → 실제 신경회로 연결. 첫 카메라 도입은 생물학적 시각 재현 또는 학습 완료가 아니다.

### 이번 설계 산출물

`docs/design/VISION-01.md`에 입력/출력/금지 채널, 좌표계·clock·지연, 관측 schema version, 평가 데이터 분리, oracle 대비표, 시각 성능/물리 성능의 독립 지표와 수용 기준 제안. 코드는 작성하지 않는다. A2/에너지 검증 상태를 보고한 뒤 영상 제어 통합 여부를 결정한다.

## 범위 제외

KC-01b 실제 다리 지지,8코스 재보정,변화구,RL 훈련,실제 신경회로 구현,시각 제어 구현은 이번 작업에서 하지 않는다. 물리 결과가 나빠졌다는 이유로 원래 결과를 삭제하거나 검증 실패를 완료로 표시하지 않는다.
