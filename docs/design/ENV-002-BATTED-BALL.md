# ENV-002 — 인필드 방향 타격과 타구 추적

규약1.0 · 2026-09-16 · 사용자 지적에 따른 목표 수정. B0/B1의 contact-only 성공 판정을 대체하는 신규 `batted-ball-v1` profile이다. 기존 접촉 실험은 회귀용으로 보존한다. [검토 증거](../records/B1-BATTING-REVIEW.md).

## 1. 목적과 스윙 방향

공에 닿는 것과 야구 타격을 구분한다. +x가 인필드/외야, -x가 포수 방향이다. 정상 스윙의 접촉점 배트 속도 vx는 양수가 되도록 설계하고, 충돌 후 실제 공이 +x 쪽으로 나가는지를 측정한다. 배트 방향 벡터나 joint 각도 부호만으로 판정하지 않는다.

현재는 +1.0rad에서 -1.3rad로 접근해 배트 vx<0이다. 첫 검토 후보는 준비각-1.9rad에서 증가하는 각도로 약-1.3rad의 접촉각을 지나가는 경로다. 이는 검증 전 후보이며 기존 관절 한계/몸 겹침/준비 틸트/후속 스윙을 재검사한다. 필요하면 관절 기준 프레임을 명확히 재설정한다. 투구 방향이나 공 속도를 인위적으로 뒤집어서 고치지 않는다.

양축 결합 상태에서 준비·가속·접촉·후속 스윙을 보정한다. 기존 oracle 트리거 표와 scripted 선형 fit은 역방향 접촉을 위해 찾은 값이므로 새 profile에서 재사용하지 않는다. oracle은 코스별 물리 도달성 진단, scripted는 관측만 사용하는 별도 제어기로 유지한다.

## 2. 접촉 이후 상태 전환

phase를 `pitch → bat_contact → batted_ball → outcome`으로 둔다. 최초 접촉은 사건이며 terminal이 아니다. 접촉 이후 pitch의 pass_x 판정은 비활성화한다. 충돌을 실제 물리 적분으로 처리하고 qvel을 원하는 방향으로 직접 설정하지 않는다.

- 접촉 직전 저장 상태, 접촉점/법선, 두 물체의 물질점 속도, contact force/impulse 집계, 접촉 지속시간을 기록한다.
- 접촉이 없어진 최초 tick을 후보 분리시각으로 잡고2ms 연속 무접촉일 때 확정한다. exit velocity는 그 후보 시각의 공 중심 선속도다. 중간 재접촉이면 후보를 취소한다. 분리 전 지면/몸/다른 물체에 닿으면 원인을 기록하고 깨끗한 타구와 구분한다.
- 접촉50ms 이내에 분리되지 않으면 `prolonged_contact` 진단. 이는 수치/재료 모델 검토 대상으로 표시한다. 이후 단순 속도반전 처리로 강제 성공시키지 않는다.
- 종료는 첫 타구 지면접촉, 경기장 경계 통과 또는 최대 비행시간10s. 제한시간은 truncated이며 미스나 정상 착지를 의미하지 않는다. 투구 중의 지면 우선 실패 규칙은 유지한다.
- 한 공의 반복 접촉 횟수와 추가 impulse를 모두 기록하고, 접촉 보상을 반복하지 않는다. 타구를 배트로 밀어내는 현상과 분리된 타격을 구분한다.

MuJoCo 접촉계수/마찰/solver/질량/관성은 분리 검증한다. 알려진 정면 충돌에서 상대속도와 impulse 방향, 에너지의 비정상 증가 여부, timestep 수렴을 확인한다. 실제 야구의 반발을 주장하려면 재료 계수를 측정/문헌에 맞춰 별도 보정한다.

## 3. 성공 지표와 첫 공학적 기준

각 투구에 contact_occurred, bat_contact_vx, exit_velocity_xyz, exit_speed, launch_angle, spray_angle, first_landing_xyz, carry_distance_xy, fence_crossing을 저장한다. 발사각=atan2(vz,hypot(vx,vy)), spray=atan2(vy,vx). 입력이0이거나 분리되지 않으면 결측 사유를 기록한다.

**첫 타격 기준 `forward_flight_success`:** 배트와 분리한 공이 지면에 닿기 전에 x=5m 기준면을 +x 방향으로 통과하고, 통과점이 |y|≤x인 인필드 부채꼴 안에 있어야 한다. 통과 위치는 인접 tick 사이에서 보간한다. 기존에 공이 투구 중 x=5m를 통과한 사건은 제외한다. 이 기준은 초기 검증용 타구 목표이지 공식 안타 판정이 아니다. 낙하가 먼저인 땅볼도 타구 기록은 남기지만 이 공중 통과 smoke 기준에서는 실패다.

지표를 `contact_rate`, `forward_exit_rate`, `forward_flight_rate`, 코스별 비거리/발사각으로 나눈다. +x 속도만 양수인 미세한 튕김을 충분한 타격으로 간주하지 않도록5m gate를 둔다. 우연한 수동 반사에 비해 능동 스윙이 무엇을 개선하는지도 비교한다.

수비수·주루·공식 페어/파울 판정이 없으면 안타라고 표시하지 않는다. 지금은 ‘전방 타구/첫 착지/비거리’를 보고한다. 홈런은 이후 구장 fence profile(거리·높이·형상)을 명시하고 땅에 닿기 전 페어 외야 담장을 넘는지를 검사하는 별도 목표다. 임의 거리 초과만으로 홈런 표시를 붙이지 않는다. 실밥/공기력 도입 전 비거리는 해당 단순 물리의 결과로 표시한다.

## 4. 보상

새 profile에서 첫 접촉 보상은0. `forward_flight_success`를 충족하면+10을1회 지급하고, 미충족 정상 종료에는-3, 제어 비용은-0.2∫(u_swing²+u_tilt²)dt. gate 보상은 같은 tick의 충돌/지면 사건을 먼저 확인한 뒤 지급한다. 외부 timeout은 truncation으로 기록하고 실패 벌점을 자동 지급하지 않는다. terminal/outcome과 보상 지급 여부를 독립 상태로 유지한다.

이것은 B1 타격 물리 검증용이며 이후 안타/홈런/선구안 목적의 RL 보상과 별도 버전이다. reward 합보다 원 타구 지표를 우선 보고한다. exit speed 크기만의 보상이나 원래 접촉+10을 남겨 뒤로 친 공이 성공하는 경로를 만들지 않는다.

## 5. 검증과 통과 기준

1. 중앙 고정 직구에서 양의 접촉점 배트 vx, 배트 분리 후 양의 공 vx, 물리적 impulse에 의한 방향 변화, 인필드 gate 통과를 확인한다.
2. 접촉만 나고 공이 -x로 계속 가는 기존 컨트롤러는 contact=true라도 forward_flight_success=false여야 한다.
3. dt0.00025/0.000125/필요시0.0000625에서 동일 시간표로 비교한다. 경계에서 충분히 떨어진 중앙 성공 사례의 출구 속도 성분 오차≤max(0.5m/s,참조성분절댓값의5%), 첫 착지 위치 차이≤0.5m를 초기 공학적 기준으로 둔다. 접촉창 수렴 기준은 I-07a-1도 유지한다.
4. 중앙 해결 후9개 코스로 확장한다. oracle은9개 모두 forward_flight_success 달성 여부를 표로 보고하며 미달 코스는 몸/접촉/구동/제어 원인을 분리한다. 접촉9/9만으로 완료하지 않는다.
5. 실제 관측 기반 scripted는 코스별 결과를 그대로 보고한다. zero_torque/held_rest/random/구 컨트롤러와 같은 투구·실행 시간으로 비교한다. oracle 성공은 학습 성공과 구분한다.

중앙 물리 성공과9개 코스 oracle 타격 도달성까지 확보한 뒤 B2를 진행한다. oracle의 역학 한계를 파라미터 임의 조작/공의 속도 보정으로 숨기지 않는다. 성립하지 않으면 설계 문제를 보고하고 재설계한다.

## 6. 영상과 후속 외형

시뮬레이션 시각으로30/60fps 장면을 샘플링한다. 접촉 전후 같은 배율(기본1×), 슬로모션은 별도 파일에 일정 배율을 표시한다. frame별 simulation_time과 playback_time을 저장한다. renderer가 물리를 진행시키지 않고, terminal 뒤 임의 mj_step으로만 보이는 타구와 채점 결과가 달라지지 않게 한다.

필수 영상은 중앙 및9코스의 투구→스윙→충돌→분리→타구 착지/종료. 포수 뒤/측면/전체화면에 +x 인필드 화살표, 공의 속도벡터, contact/forward_success를 debug overlay로 보여준다. 정책 카메라에는 이 정답 overlay를 제외한다. 카메라는 타구를 따라가거나 전체화면으로 전환해 궤적을 끝까지 볼 수 있어야 한다.

현재 캡슐 타자를 파리로 표현하는 외형 작업은 VIZ 후속이다. 날개/다리/몸통의 visual mesh를 단순 물리 rig와 분리하고 렌더링 장식으로 역학이 바뀌지 않게 한다. 우선 실제 타격 운동을 고친다.

## 거리 보상 후속 버전

위 보상은 기존 batted-ball-v1 기록이다. 사용자 요청에 따른 다음 구현은 [forward-carry-v1](BATTING-QUALITY-AND-SWING.md)을 적용한다. 기존+10 gate 보상과 새 거리 보상을 중복하지 않는다.
