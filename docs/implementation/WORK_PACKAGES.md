# Claude 구현 인계

2026-09-16 · 사용자와 Codex가 계획·설계를 담당하고, 실제 코드·테스트는 사용자와 Claude가 진행한다. 이 문서는 작업 명세이며 완료 보고가 아니다.

## 착수 순서

**I-01 → I-02**, 이후 **I-03은 독립 작업**, **I-04는 연구 선택을 기다리며 합성 fixture 기반의 기반 기능까지 진행 가능**, **I-05는 EXP-001 확정 후** 진행한다. 사용자가 지정한 범위가 우선한다. 전면적인 폴더 이동이나 모든 단계의 일괄 구현을 요구하지 않는다.

### I-01. 실행환경과 현재 상태 확인

- 프로젝트 전용 Python/의존성 환경을 선정하고 최소 core와 RL/SNN 옵션을 분리한다.
- 논문 재현 환경과 프로젝트 실행 환경의 버전 충돌 가능성을 조사하고 실제 설치 조합을 고정한다.
- 초기 import·환경 로드·패키징·수치 실행을 검증한다. 새 모듈 추가 시 배포 패키지 포함도 확인한다.
- 운영체제·의존성·backend·소스 식별자를 기록하고 소스/데이터/실행 결과 저장 정책을 마련한다.

**완료 증거:** 정확한 환경 조합과 재현 명령, 실제 성공·실패 결과, lockfile. 렌더링은 별도 검사로 둔다. 런타임 검증과 학습 성공을 구분한다.

### I-02. 설정·공통 기록·상태 계약

- [구조 계약](../design/ARCHITECTURE.md), [설정 명세](../../configs/README.md)에 맞춰 최소 실행기·검증·저장 경로 구현.
- 기존 YAML을 실제 실행에 연결할지 legacy 전용으로 둘지 명시. 적용되지 않는 설정을 성공으로 표시하지 않음.
- 시드·단위·실행 상태·설정 형식 버전·checkpoint 분리 구현.
- 신경·물리 시계, probe 분기, fast/slow/trace reset 계약을 작은 합성 모델로 확인.

**완료 증거:** 설정 변경이 실제 출력에 반영됨; 잘못된 설정 거부; 동일 seed 재현; 중단·재개 비교; 평가 중 학습 상태 불변; probe 간 상태 오염 없음. 합성 검사는 실제 연결망 학습 결과로 보고하지 않는다.

### I-03. 기존 타격 환경의 결함 수정

근거: [정적 진단](../records/PROJECT_AUDIT_2026-09-16.md). 2026-09-16에 아래 8개 항목을 수정했다(`envs/fly_batter_env.py`, `envs/assets/fly_batter.xml`, `demos/record_episode.py`, `tests/test_fly_batter_env.py`). 실행 증거는 `docs/records/VALIDATION_LOG.md`.

| 수정 항목 | 완료 기준 | 상태 |
| --- | --- | --- |
| 발사 속도에 중력 보정 | 무동작 자유 궤적이 의도한 목표를 허용 오차 안에서 지남; 지면에 먼저 충돌하지 않음 | 완료. `model.opt.gravity` 기반 발사식 보정 + `envs/assets/fly_batter.xml`의 `ball_free` 관절에 있던 의도치 않은 `<default>` damping(0.02) 제거(발사식만으로는 목표에 도달 못 함을 발견해 추가로 고침) |
| 물리 substep별 접촉 수집 | 중간 step 접촉 누락 없음, 최초 시각 보존, 한 접촉의 중복 보상 방지 | 완료. `frame_skip` 루프 안에서 매 substep 접촉·zone-crossing 검사, 최초 발생 시각 기록, `hit_step is None` 게이트로 중복 방지 |
| 접촉점 상대 선속도 | 선속도·각속도 단위 혼합 제거, 알려진 운동으로 검증 | 완료. `mj_jac` 기반 접촉점 물질점 속도(m/s)로 교체. 단, mj_step 이후(충돌 해석 후) 속도라 "충돌 직전 속도"와는 다를 수 있음 — 단위 혼합만 해소, 타이밍 미세조정은 별도 |
| 타이밍 평가 | '도착까지 시간'과 실제 행동/접촉 오차 분리, 실패 시 결측 이유 명시 | 완료. 관측의 예측값과 `info["timing_error"]`(실제 hit-crossing 차이, 미해당 시 `None`+`timing_error_missing_reason`)를 분리 |
| 제어 비용 | 행동 제곱은 제어 비용으로 명명; 물리 에너지는 계산한 경우에만 별도 표시 | 완료. `energy_cost`→`control_cost`로 개명(물리 에너지 계산은 없음) |
| 보상·종료 의미 | hit/miss/지면 접촉/시간 제한을 구분; 제어 주기 변경 효과와 누적 보상 점검 | 완료. `info["end_reason"] ∈ {hit, ground_contact, passed_no_contact, timeout}` 구분 도입. 매 step 누적되던 timing 기반 보상 항을 제거해(원인 진단은 I-01 기록 참고) 보상 폭주 버그 해소 |
| 관측·baseline | 같은 정보 조건 정의, scripted·무동작·무작위의 검증 궤적 비교 | 완료(측정, 목표 미달성). `demos/record_episode.py --controller all`로 동일 조건 비교 가능해짐. **측정 결과 scripted/none/random 모두 hit_rate=1.000** — 정지된 팔이 이미 공 경로를 막고 있어 현재 팔 배치로는 제어 능력을 변별할 수 없음(새 발견, 미수정) |
| 렌더링·녹화 설명 | 실제 지원 기능과 이름·문서를 맞춤; 필요 시 창/영상 구현은 별도 단위 | 완료(문서만). `render_mode="human"`이 창을 띄우지 않음을 docstring/README에 명시. 실제 뷰어/영상 구현은 하지 않음(별도 단위로 유지) |

현재 중력 환경의 의도를 유지하는 발사식 보정을 기본 방향으로 했다(무중력으로 바꾸지 않음). 타이밍의 세부 정의(허용 오차 숫자)는 여전히 미정이며, `info["timing_error"]`는 정의만 제공하고 통과 기준 수치는 채우지 않았다(EXP-001 Q-05 영역).

**완료 증거:** `tests/test_fly_batter_env.py`(7개 테스트, 결정적 시나리오로 중력 보정/substep 접촉/접촉속도/지면접촉 구분/제어비용/타이밍 결측·존재를 각각 재현), `demos/record_episode.py --controller all`의 baseline 비교 실행. 자세한 명령·수치는 `docs/records/VALIDATION_LOG.md`.

**새로 발견해 미해결로 남긴 항목:** 팔의 정지 위치를 "타자처럼" 뒤로 젖힌 자세(`SWING_REST_ANGLE=1.1`)로 바꾸고 `ScriptedSwingController`도 그에 맞게 다시 짰지만(2026-09-16), **회전각 -1.4~+1.3 rad 11개 전부에서 무동작 baseline hit rate가 여전히 1.000**이었다(`docs/records/VALIDATION_LOG.md`의 후속 기록). 원인은 현재 중력 보정 발사식이 고정 목표점에 정확히 도달하기 위해 정점 높이 1.12~1.69m짜리 큰 포물선을 요구하는데, 힌지-목표점 거리(~0.143m)가 팔 길이(0.58m)보다 훨씬 짧아 팔의 도달 반경 안에 목표점이 항상 들어있기 때문이다. **즉 정지 자세를 어디로 옮기든 이 기하학적 구조상 해결되지 않는다.** 실제로 제어 능력을 변별하려면: (a) `flight_time`/높이 범위를 좁혀 궤적 정점을 낮추거나, (b) 목표점을 힌지에서 더 멀리 두거나, (c) 팔에 자유도/도달거리 여유를 더 주는 등의 **과제 기하 설계 결정**이 필요하다 — 임의로 바꾸지 않고 사용자/Codex 확인을 기다린다.

### I-04. 실제 회로·가소성 구성

- 2026-09-16 기준 Q-01~04는 [`../PLAN.md`](../PLAN.md)(D01~D09)와 [`../design/DATA_MODEL.md`](../design/DATA_MODEL.md)에서 해결되었다: MaleCNS v1.0, mcns-kc-mbon11-v1(KC→MBON11), MBON LIF + `dopamine_gated_depression` 규칙. 이 값을 기본으로 dataset loader·회로 ID·경계·부호·조절 신호를 구현한다.
- 원 논문 프로토콜을 재현하고 선택한 dt에서 수치 안정성·입력 세기별 반응을 검증한다.
- 학습 연결만 갱신하며 비대상 연결과 고정 readout의 불변성을 검증한다.
- 실제 전달물질 정보와 모델에서 가정한 효과를 분리해 기록한다.

**선행 조건:** [설계 결정](../DECISIONS.md)의 논문·데이터·회로·방정식(일반 원칙). 결정 전에도 loader 계약, 합성 데이터와 상태 저장 검사는 가능하다.

**완료 증거:** 출처 manifest, 실제 ID 연결, 원 프로토콜 재현 결과, 모델링 가정, fast/slow/trace 분류표. 기존 toy SNN에 이름만 붙여 실제 회로라고 보고하지 않는다.
