# 학습 01 — 회로 파라미터 탐색 (Phase 5 첫 실행)

2026-09-18 · 구현 `flyohtani/task/{pitches,rewards,learn}.py` ·
원자료 `runs/learn/*.json` · 회귀 `tests/test_task_learning.py`

## 결론

**훈련 투구에서는 배웠고(보상 0.218 → 0.571), 처음 보는 투구에서는 눈을 못 쓰는
정책과 비슷하거나 약간 못했다.** 즉 **일반화하지 못했다.**

| | 접촉률 | carry-v1 보상 |
| --- | --- | --- |
| 학습된 회로 정책 | **0.23** | 0.267 |
| 고정 프레임 20 (눈 안 씀) | 0.17 | **0.293** |
| 고정 프레임 22 (눈 안 씀) | 0.17 | 0.200 |
| 고정 프레임 18 (눈 안 씀) | 0.00 | 0.000 |

평가 투구 30개는 **학습에 한 번도 쓰이지 않았다**(`pitches.py`에서 시드 분리,
실행 전 고정). 접촉은 조금 나아졌지만 보상 기준으로는 기준선을 넘지 못했다.

## 왜 일반화하지 못했나 (진단)

### 1. 훈련 투구가 18개뿐이라 외웠다

세대별 훈련 보상: 0.218 → 0.391 → … → 0.571. 평가에서는 0.267.
18개 투구의 특정 타이밍에 맞춘 것이다.

### 2. 존을 읽는 신호가 약하다

평가 투구를 존별로 뜯으면:

| 투구 존 | 접촉 | 존 일치 |
| --- | --- | --- |
| 낮은 공 | 4/10 | **10/10** |
| 높은 공 | 2/10 | 5/10 |
| 가운데 | 1/10 | **0/10 (구조적)** |

정책은 `high`/`low` 두 가지만 출력한다. 가운데 존은 **이 눈으로 낮은 공과 구분되지
않아서**(변별력 d = 0.46) 2분할로 줄였고, 그래서 가운데 투구는 원리상 맞힐 수
없다. 높은/낮은 공만 보면 존 일치 **15/20 (75%)**.

### 3. 위치는 시간과 얽혀 있다

존을 "공이 화면에서 어디 있는가"로 읽으려 했을 때 우연 수준(31%)이 나왔다.
공이 다가오며 화면에서 계속 올라가기 때문에(행 17 → 11), **위치는 존보다 경과
시간을 훨씬 강하게 담는다.** 회로가 커밋하는 시점이 투구마다 달라서, 그 시점의
위치를 읽으면 두 정보가 섞인다.

그래서 **올라가는 속도**로 바꿨다(높은 공 −0.17 행/프레임, 낮은 공 +0.01). 이건
시간에 따라 표류하지 않는다. 다만 변별력이 d = 1.8로, 이 정도가 지금 한계다.

## 도중에 고친 실제 버그

**릴리스 지점이 존에 따라 움직이고 있었다.** 릴리스를 타격 지점에서 역산하다
보니(거리가 3.6배라 지렛대가 반대로 작용), 타격점을 0.45 mm 올리면 릴리스가
**1.16 mm 내려갔다.** 그 결과 높은 공이 눈에 **더 낮게** 보였다 — 파리가 읽어야
할 신호가 거꾸로 뒤집혀 있었다. 투수의 손은 존과 무관하게 고정돼야 한다.
`pitch_geometry(release_reference=...)`로 고쳤고, 고친 뒤 순서가 바로잡혔다.

## 다음에 할 만한 것

측정된 것에서 바로 따라 나오는 순서다.

1. **훈련 투구를 늘린다.** 18개는 외우기 좋은 수다. 100개 이상 + 세대마다 다시
   뽑기.
2. **과제를 2분할로 정의한다.** 지금 평가 세트는 정책이 표현할 수 없는 존을
   1/3 포함한다. 눈이 구분 못 하는 것을 과제에 넣어 둔 셈이다.
3. **존 신호를 키운다.** 존 간격 0.80 mm는 이 눈에서 약 1픽셀이다. 눈을 더
   예민하게 하거나(이미 실제 파리의 6배), 존 간격을 넓히거나(스트라이크 존이
   비현실적으로 커진다), 신호를 시간에 걸쳐 더 모으는 방법.
4. **가소성.** 지금은 5개 파라미터 탐색이다. 시냅스 가중치를 보상으로 조절하는
   쪽으로 가면 회로 자체가 학습 대상이 된다.

## 2차 — 스윙을 고친 뒤 (D35·D36)

투수판 투구와 밀어치는 스윙으로 바꾼 뒤 같은 탐색을 다시 돌렸다
(`evidence/LEARNING-01-d36-carry-v1.json`).

| | 접촉률 | 페어 | carry-v1 보상 |
| --- | --- | --- | --- |
| **학습된 회로 정책** | **0.30** | **0.23** | **0.877** |
| 최고 맹목 기준선(프레임 14) | 0.20 | 0.13 | 0.471 |

**처음으로 기준선을 확실히 넘었다** — 보상 1.86배, 접촉 1.5배. 1차에서
무승부였던 것과의 차이는 두 가지다: 기준선을 공정하게 고쳤고(프레임 3개 →
6~25 전부에서 최고), 스윙이 실제로 공을 밀어치게 됐다.

### 재현: 시드 3개 전부 기준선을 넘었다

| 시드 | 훈련 보상 추이 | 평가 보상 | 접촉 | 페어 |
| --- | --- | --- | --- | --- |
| 3 | 0, 0, 0, 0, 0, 0, 0, 0, **0.68** | **0.877** | 0.30 | 0.23 |
| 4 | 0, 0, 0, 0, 0, 0, 0.15, 0.51, **0.51** | **0.566** | 0.30 | 0.10 |
| 5 | 0, 0, 0.12, 0.47, 0.47, 0.53, … **0.53** | **0.613** | 0.23 | 0.20 |
| — | 최고 맹목 기준선 | 0.471 | 0.20 | 0.13 |

**3/3이 기준선을 넘었다**(평균 0.685, 기준선의 1.45배). 다만 **보상이 희소하다**:
시드 3은 8세대 중 7세대를 빈손으로 보냈고, 시드 5는 3세대에 신호를 잡았다.
접촉 창이 좁아 탐색이 처음 맞힐 때까지 아무 신호가 없다는 뜻이고, 세대 수가
적으면 운에 크게 좌우된다.

### 학습된 정책의 실제 타구

같은 정책으로 투구를 훑으면 페어 타구가 여럿 나온다(비거리 37~52 mm). 녹화한
것은 높은 공 −3.5 ms: 정책이 **27.1 ms에 스스로 커밋**해 `high` 존을 고르고,
타구 808 mm/s · 발사각 +10° · **비거리 28.9 mm(사람 환산 14 m) 페어**.
`runs/record/learned-hit`.

## 이 결과가 말하지 않는 것

- **"연결망이 학습했다"고 말할 수 없다.** 배운 것은 디코딩의 상수 5개다.
- **"파리가 스스로 친다"는 2차에서 말할 수 있다.** 처음 보는 투구에서 눈 없는
  최고 기준선을 **시드 3개 모두** 넘었다(평균 0.685 vs 0.471). 다만 접촉률은
  0.23~0.30이다 — 네 번에 한 번 맞히는 타자다.
- 다만 **회로가 공을 보고 타이밍을 잡는다**는 것은 별도로 확인돼 있다
  ([BRAIN-CIRCUIT.md](BRAIN-CIRCUIT.md)): 투구가 2 ms 늦으면 트리거도 정확히
  1프레임 늦는다. 부족한 것은 그 신호를 행동으로 옮기는 부분이다.
