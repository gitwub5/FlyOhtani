# B1 검토 — 접촉 성공과 타격 성공의 혼동

2026-09-16 · 기준 commit c812766. 사용자 영상 지적을 받고 Codex가 코드, 저장 영상의 프레임,9개 oracle 궤적을 확인했다. 구현은 수정하지 않았다.

## 확인 결과

+x는 투수/인필드, 공은 -x로 들어온다. 현재 준비 스윙각+1.0에서 약-1.3 방향으로 회전하므로 공과 만나는 배트의 물질점도 -x로 움직인다. 팔이 공을 뒤따라 포수 쪽으로 휘둘리는 방향이다. `controllers/baseball_b1.py`의 목표각 접근 방식은 정렬/접촉을 달성하지만 반대 방향으로 보내는 타격을 요구하지 않는다.

`envs/baseball_b1_env.py`의 step은 첫 bat_hit에 hit로 종료하고, reward는 그 접촉에+10을 준다. 공에 충격량이 충분히 전달되고 배트에서 분리되어 인필드로 나가는지는 평가하지 않는다. B0도 같은 접촉 중심 구조다. 이전 9/9는 접촉 도달성이고 안타/유효 타구 성공률이 아니다. 앞선 Codex 계획이 이 기준으로 진행을 안내한 점도 수정한다.

## 독립 수치 진단

각 course에 OracleAimController, seed0을 적용했다. env가 끝난 시점의 접촉점에서 Jacobian으로 배트 속도를 얻었다. 이어 원본 파일은 바꾸지 않고 마지막 ctrl을 유지한 채 mj_step400회(dt0.00025,100ms)를 수행했다. 이는 기존 종료 뒤의 진단 연장이며 새 타구 평가기나 배트 분리시각의 exit velocity 측정은 아니다.

| 코스 | 접촉점 배트 vx(m/s) | 100ms 연장 뒤 공 vx(m/s) |
| --- | --- | --- |
| in_high | -6.487 | -34.413 |
| in_mid | -7.044 | -30.356 |
| in_low | -4.851 | -34.725 |
| mid_high | -8.977 | -33.559 |
| mid_mid | -9.319 | -30.858 |
| mid_low | -8.162 | -33.037 |
| out_high | -12.298 | -33.835 |
| out_mid | -11.356 | -31.820 |
| out_low | -10.297 | -30.707 |

9코스 모두 접촉하지만 공은 계속 -x 방향이다. 단순히 joint torque의 부호만 바꾸면 된다는 결론은 아니다. 준비각·스윙 경로·접촉면 법선·상대속도·충격량·접촉 종료 후 공 속도를 함께 검증해야 한다.

## 영상 시간 문제

`runs/env002-b1-demo/video/in_mid/behind_catcher.mp4`의 프레임을 확인했다. `demos/record_baseball_b1_episode.py`는 접촉 전 매 control step(5ms), 종료 뒤 매 physics step(0.25ms)을 같은30fps로 저장한다. 앞부분은 약6.67배, 뒷부분은 약133.33배 느리며 재생 배율이20배 바뀐다. 종료 후60프레임은 실제로15ms뿐이다. ‘타구가 날아가는 영상’으로 판정하기에 부적절하다.

추가로 영상 속 타자는 현재 파리 외형이 아니라 파란 캡슐이다. 물리 기구와 분리된 파리 시각 자산은 아직 별도 작업이 필요하다. 이번 우선 수정은 타격 방향·타구 판정·시간축이다.
