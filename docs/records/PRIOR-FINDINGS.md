# 선행 실험에서 확정된 사실

2026-09-17 작성. v1(사람 크기 구장 + 3축 강체 배트 + KC-01a 협응 탐색)에서
얻은 결과 중 **v2에서 다시 밟으면 안 되거나 그대로 재사용할 것만** 남긴
요약이다. 원본 문서·원자료·스크립트는 전부 git 태그
`archive/human-scale-v0`에 있다.

읽는 사람에게: 아래 수치는 전부 **옛 스케일(사람 크기 구장, 확대된 파리)**
에서 나왔다. v2는 파리 실물 스케일이므로 **수치를 그대로 옮기지 말고
방법론과 실패 원인만 가져온다.**

## 1. 단위 규약 — 확정, 그대로 사용

NeuroMechFly/flygym의 MJCF는 **길이 mm, 질량 g**를 기본 단위로 쓴다.
따라서 힘은 자동으로 **μN**(g·mm·s⁻²)이 된다. 공식 문서에서 직접 확인했다:

> "we use millimeter and gram as base units for length and mass instead of
> their SI counterparts, meter and kilogram... forces read out from the
> simulation are in g·mm·s⁻¹ (i.e., micronewton, μN)"
> — <https://neuromechfly.org/tutorials/1b_advanced_model_composition/>

- 전신 raw 질량 합 = 0.001 g = **1 mg** (성체 초파리 문헌값과 같은 자릿수)
- 앞다리 전체 = 13.89 μg. 세그먼트 비율(스케일 불변, 그대로 채택):
  **Coxa 32.6% : Femur 45.3% : Tibia 14.9% : Tarsus1 3.3% : Tarsus2–5(수동) 3.9%**
- 원본 위치제어 기본값: `kp=45`(raw) = 4.5×10⁻⁸ N·m/rad,
  `forcerange=±65`(raw) = ±65 nN·m, `joint_damping=0.06`,
  `joint_stiffness=0.05`, Tarsus 수동 스프링 `stiffness=7.5, damping=0.01`

> **한 번 틀렸던 지점**: raw XML의 질량을 정규식으로 합산할 때
> `<statistic meanmass="1.0">`(시각화 메타데이터, 물리량 아님)까지 잘못
> 더해 "질량 합 ≈ 1.0"이라는 측정 오류가 나왔다. 실제 합은 0.001이다.
> 질량을 셀 때는 컴파일된 `model.body_mass`를 쓴다.

## 2. 접촉 검증 — 사전 등록 수용치 (v2에서 그대로 재사용)

**결과를 보기 전에 고정된 기준이다. 결과가 나쁘다고 완화하지 않는다.**

| 항목 | 수용치 |
| --- | --- |
| 관통 깊이 | ≤ 30% × min(공 반지름, 배트 반지름) |
| 반발계수(COR) | 0.3 ~ 0.7 |
| dt 수렴 오차 | 가장 미세한 두 dt 사이 COR·관통·충격량 차이 ≤2%(또는 절대 0.01) |
| 에너지 잔차 | production dt에서 ≤5% of 충돌 전 운동에너지 |
| 자유 배트 운동량 보존 | 총 운동량 변화 ≤1% |

이 값들은 **공학적 여유 기준이며 이 특정 재질쌍의 실측 문헌값이 아니다.**
그렇게 기록되어 있으므로 "실제 야구 재료를 재현했다"고 말하지 않는다.

## 3. 접촉 실패 — 원인은 분리됐고, 재료 문제는 미해결

v1의 접촉 검증은 **FAIL**로 끝났다. 원인 분리까지는 완료했다.

**해결된 것 — 기하 결함(다시 만들지 말 것)**: 공 반지름(0.0366 m)이 타격판
두께의 절반(0.01 m)보다 커서, 공 중심이 판을 관통하는 동안 박스-구 접촉의
법선 x부호가 −1 → +1로 뒤집혔다(직접 관측). 그 결과 반발계수가 **음수
(−0.298)** 로 나왔다. 두꺼운 블록이나 진짜 평면으로 바꾸면 부호 문제가
사라진다.
→ **v2 규칙: 타격체의 관통 방향 두께가 공 지름보다 얇으면 안 된다.**

**미해결 — 재료 자체**: 기하를 고쳐도 남는 값들이다.

| 대상 | COR (dt=2.5e-4 / 6.25e-5 / 7.8e-6) | 침투 |
| --- | --- | --- |
| 두꺼운 블록 | +0.294 / +0.291 / +0.292 | 0.048 m |
| 평면 | +0.286 / +0.294 / +0.292 | 0.047 m |
| 자유 배트 0° / 20° / 35° | 0.294 / 0.284 / 0.293 | 0.048 / 0.044 / 0.040 m |

즉 COR ≈ 0.29는 **dt에 잘 수렴하지만 기준 0.3~0.7에 근소 미달**이고,
침투 0.04~0.05 m는 기준을 크게 미달한다. 입사각(0°/20°/35°)과 무관하다 —
"비스듬한 충돌이라 봐줄 만하다"는 논리는 데이터로 성립하지 않는다.

→ **v2에서 남은 일**: 새 진단 profile에서 `solref`/`solimp` 후보를 비교해
COR을 대역 안으로 올린다. 스케일이 줄면 공 질량이 길이³로 급감해 침투
**절대량**은 작아지지만, **반지름 대비 상대 침투**는 별개라 반드시 실측한다.

## 4. dt 발산의 원인 — 접촉 계산 자체 (진단 방법론 재사용)

KC-01a 협응 조건들이 물리 timestep에 따라 결과가 뒤집히는 문제의 원인을
분리 실험으로 확인했다(추정 아님):

- **구동 전용**(공 없이 관절만 구동) → 완벽히 dt 수렴
- **접촉 전용**(동일한 충돌 직전 상태를 재생) → 같은 패턴으로 발산

→ Phase 1의 G1(무공 스윙)이 dt 수렴을 통과할 가능성은 높고, Phase 2의
G2(접촉)가 진짜 관문이다. 같은 분리 방식을 v2에서도 쓴다.

관련 교훈 둘:
- 에너지 잔차를 계산할 때 관절한계 반력(`qfrc_constraint`)을 빼먹으면
  잔차가 부풀려진다. 이를 포함하자 잔차가 0.5~4.2%로 설명됐다.
- 남은 잔차를 "semi-implicit Euler 절단오차"로 설명했던 보고는 **틀렸다** —
  XML은 `integrator="RK4"`였고 실제 원인은 분석 스크립트 자신의 work 적분
  (quadrature) 오차였다. 적분기를 확인하고 쓴다.

## 5. 시각 — 검출 한계는 픽셀 크기가 결정한다

head 부착 카메라(`eye_cam`) + 색상 기반 검출기 + 칼만 추적기로 측정한
결과(옛 스케일, 단일 투구 31프레임):

| 해상도 / FOV | recall | precision |
| --- | --- | --- |
| 320px / 60° | **96.4%** | 1.0 |
| 128px / 60° | 42.9% | 1.0 |
| 128px / 90° | **17.2%** | 1.0 |

recall을 가른 것은 **공이 화면에서 몇 픽셀인가** 하나였다:

| 거리 구간 | mean_n_pixels | 검출률 |
| --- | --- | --- |
| near | 4.3 px | 90% |
| mid | 0.33 px | 33% |
| far | 0.0 px | 0% |

→ **v2 규칙: 해상도/FOV를 고르기 전에 "공이 릴리스 시점에 몇 픽셀인가"를
먼저 계산하고 실측한다.** 서브픽셀 구간에서는 어떤 검출기도 실패한다.
precision이 항상 1.0이라는 점도 기억해 둔다 — 이 검출기는 헛것을 보지
않고, 못 볼 뿐이다.

칼만 추적기(등속도)는 가림 구간에서 평균 위치 오차를 42.2 px → 30.3 px
(28% 개선)로 줄였지만, **정상 구간에서는 필터 지연 때문에 0.91 → 1.21 px로
오히려 악화**됐다. 둘 다 보고한다.

## 6. 입력 누출 방지 — 그대로 유지

정책 경로가 시뮬레이터의 정답 상태를 보지 못하게 하는 장치가 v1에서
동작했고, v2에서도 유지한다:

- `VisionObservation`은 `**kwargs` 없는 frozen dataclass이고, 금지 이름
  목록(`ball_pos`, `ball_vel`, `remaining`, `course`, `phase`, ...)을
  `__post_init__`에서 검사한다. 채널을 추가하려면 필드 목록을 손으로
  고쳐야 하고, 그게 의도다.
- 정답을 읽는 코드는 `sense/evaluator.py` **하나뿐**이고, 정책 경로
  모듈이 그것을(또는 환경 모듈을) import하지 않는다는 것을 **AST 정적
  검사 테스트**로 강제한다.
- 미검출 프레임에서 정답으로 fallback하지 않는다. 마지막 추정치를 age와
  커진 불확실성과 함께 넘긴다.

## 7. 폐기된 접근 — 반복하지 말 것

- **인간식 타격 자세의 수작업 최적화**(몸통 선행, 동방향 회전, 고정 스윙
  변위, 팔로우스루 상태기계). 후보 탐색에 스크립트 6,700줄을 쓰고 결론을
  내지 못했다. 한때 "최고 성적"으로 보고된 조건은 dt를 정밀화하자 무효로
  뒤집혀 철회됐다.
- **탐색 범위가 만든 가짜 결론**: torso 목표각을 음수 범위만 훑는 바람에
  몸통과 배트가 서로 상쇄하는 조건이 "최적"으로 뽑혔다. 후보를 채택하기
  전에 방향 일치·최소 변위·관절범위 여유를 **사전 검사**한다.
- **관절 하드 스톱에 눌린 것을 "정착"으로 읽은 것**: 팔로우스루 목표가
  관절 범위 밖이면 멈춘 것처럼 보인다. 정착 판정에 범위 여유 검사를 넣는다.
- **`mocap=true` 시각 오버레이를 몸으로 취급한 것**: 관절도 질량도 없는
  IK 오버레이였다. v2의 앞다리는 실제 물리 관절이다(D22).
