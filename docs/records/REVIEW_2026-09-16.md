# Claude 작업 검토와 원인 재진단

검토 기준: commit `e2447bb`, 2026-09-16. Codex가 기존 테스트 재실행·짧은 진단을 수행했다. 구현 파일은 변경하지 않았다. 과거 기록의 ‘기하학적 필연’ 결론은 아래 증거로 정정한다.

## 판단

I-01의 환경 고정, 중력 보정, 공 자유관절 damping 제거, 접촉점 속도의 단위 수정은 적절하다. 기존 테스트도 8개 모두 통과한다. 그러나 **I-03 전체 완료와 ‘액추에이터 충분’은 아직 입증되지 않았다.** 무토크를 정지로 취급했고, 초기 관통을 검사하지 않아 충돌 반발이 baseline과 구동력 측정에 섞였다.

## 발견 사항

### P0 — 시작 자세가 지면을 관통하고 몸통과 팔도 겹침

`envs/fly_batter_env.py`의 SWING_REST_ANGLE=1.1, XML의 힌지 H=(0.02,0,0.39), 팔 길이0.58/반경0.018에서 팔 끝 하단은 `0.39−0.58 sin(1.1)−0.018 = −0.1449 m`다. reset 직후 MuJoCo contact.dist도 ground–limb에서 -0.1449m, thorax–limb에서 -0.0567m를 보고한다. 지면 충돌과 몸통 자기충돌을 제거/정의하기 전에는 타격 과제 성능을 해석할 수 없다.

`frame_skip=1`, seed=0, zero torque에서 시작각 +1.1은 약0.712s 뒤 hit 시점에 -1.2466rad로 바뀐다. 공은 당시 약(0.0255,0.0003,0.5975)m다. **zero_torque는 움직이는 수동 시스템이고 held_pose는 별도 진단 조건**이다. hit_rate=1 측정은 재현되지만 ‘정지 팔이 모든 각도에서 맞는다’는 해석은 성립하지 않는다.

### P1 — 액추에이터 충분성 측정도 초기 충돌에 오염

메모리상의 모델에서 몸통·공 충돌을 꺼 분리하고 지면과 겹치지 않는 자세에서 최대 음의 입력을0.5s 주었다. 원본 파일·gear는 바꾸지 않았다.

| 시작각 | 초기 contact 수 | 0.5s 뒤 각도 | 최종 각속도 |
| --- | --- | --- | --- |
| 0.0rad | 0 | -0.03173rad | -0.07338rad/s |
| +0.5rad | 0 | +0.44742rad | -0.11668rad/s |

기존의 ‘0.5초에2.4rad’와 큰 차이다. gear0.01이 새로운 과제에 충분하다고 단정할 수 없다. 수동 중력·damping과 함께 별도 식별해야 한다. 위 분리 실험은 진단이며 실제 환경에서 몸통의 모든 충돌을 끄라는 구현 지시가 아니다.

### P1 — 한 control step 안에서 지면 충돌보다 뒤의 hit가 우선될 수 있음

`step()`은 모든 substep을 끝까지 적분하고 `hit_now`를 `ground_now`보다 우선한다. 먼저 지면에 닿은 뒤 팔에 맞는 경우에도 성공 처리할 수 있다. 최초 terminal 사건에서 중단하고 동일 substep 동시 사건의 우선순위를 명세해야 한다. 현재 테스트에는 ‘중간 substep에서만 접촉’과 ‘지면→팔’ 순서 검증이 없다.

### P1 — passed_no_contact의 종료 분류

현재 지나친 공은 `truncated=True`다. 이번 과제에서는 공이 영역을 지나가면 실패가 결정되는 MDP terminal이므로 `terminated=True`로 정의한다. timeout만 외부 시간 한도 truncation이다. 부트스트랩 의미가 달라진다. [Gymnasium 설명](https://gymnasium.farama.org/tutorials/gymnasium_basics/handling_time_limits/)

### P2 — 지표와 테스트 보완

- 실제 충돌 뒤의 zone crossing을 기다리는 timing_error는 hit 조기 종료 때문에 흔히 결측이다. 명목상 무충돌 목표 도달시각을 기준으로 바꾼다.
- 제어 비용은 action² per step이어서 control_dt에 의존한다. 시간 적분 비용으로 정의한다.
- `_get_obs()` 후 `_prev_contact`를 갱신하므로 접촉 관측의 시점이 이름만으로 불명확하다. 반환 관측은 현재 사건, 혹은 명시적인 이전 control-step 사건 중 하나로 고정한다.
- contact.dist≤0의 실제 표면 접촉과 감지 범위 내 접촉을 구분하고, 기록 위치/속도/시각을 같은 상태에서 얻는다. 현재 속도를 충돌 직전 속도라고 부르지 않는다.
- timing 테스트는 접촉 재현 실패 시 skip한다. 핵심 회귀 fixture는 결정적으로 구성하고 실패를 skip으로 숨기지 않는다.

## 수정 방향

[ENV-001](../design/ENV-001-interception.md)의 단일 관절 설계를 적용한다. 초기 관통·연결부 자기충돌 → 구동력 재검증 → 외곽 목표/낮은 궤적 → baseline 구분 순서다. 자유도 추가는 지금 필요 없다. ‘도달 원 안의 점’과 ‘현재 각도의 캡슐이 차지하는 영역’은 서로 다르다.

## 재현 방법

프로젝트 환경에서 기존 테스트: `.venv/bin/python -m pytest tests/test_fly_batter_env.py -q` → **8 passed in 0.23s**. 이는 아래 추가 요구까지 통과했다는 뜻이 아니다.

초기 contact와 zero-torque 결과 재현:

```python
import mujoco
import numpy as np
from envs.fly_batter_env import FlyBatterEnv

env = FlyBatterEnv(frame_skip=1)
env.reset(seed=0)
print([(mujoco.mj_id2name(env.model, mujoco.mjtObj.mjOBJ_GEOM, c.geom1),
        mujoco.mj_id2name(env.model, mujoco.mjtObj.mjOBJ_GEOM, c.geom2),
        float(c.dist)) for c in env.data.contact])
for _ in range(800):
    _, _, terminated, truncated, info = env.step(np.zeros(1))
    if terminated or truncated:
        print(env.data.time, env.data.qpos[env.swing_qpos_adr], info)
        break
env.close()
```

구동력 분리 재현: 위 reset 뒤 thorax와 ball의 geom_contype/conaffinity를 각각0으로 두고, swing qpos=0 또는0.5, qvel=0, `mj_forward` 후 ctrl[0]=-1로 설정한다. `mj_step`을250회 수행하고 qpos/qvel을 기록한다. 이 검토에서 사용한 dt는0.002s다. 작업 중 `data`가 갱신되는 시점은 [MuJoCo 계산 설명](https://mujoco.readthedocs.io/en/stable/computation/index.html)을 따른다.
