# FlyOhtani v2 — 연구 계획과 설계 결정

2026-09-17 작성. 이 문서가 **결정의 단일 기준**이다. 이전 계획
(사람 크기 구장 + 3축 강체 배트 + KC-01a 협응 탐색)은 이 계획으로 대체됐고,
그 시점의 코드/문서 전체는 git 태그 `archive/human-scale-v0`에 보존돼 있다.
다시 밟으면 안 되는 지뢰는 [선행 실험에서 확정된 사실](records/PRIOR-FINDINGS.md)에
압축해 남겼다.

## 연구 질문

실제 초파리 연결망에서 유도한 회로가, 눈으로 들어오는 영상만으로 다가오는
공의 도달 시각을 추정하고 앞다리를 구동해 공을 쳐낼 수 있는가. 그리고 그
회로가 보상에 따라 **학습**하는가.

"실제 연결 데이터 + 가정한 뉴런 동역학 + 가정한 가소성"을 검증하는 것이며,
연결망만으로 실제 뇌를 재현했다고 주장하지 않는다. 일반 정책(수작업/RL
컨트롤러)은 **환경 기준선**이고, 실제 회로의 우위 주장은 셔플 배선·고정
회로 대조군을 갖춘 뒤에만 한다.

## 전체 구조

```
눈 카메라 → 망막 인코딩 → [실제 커넥톰 루밍 회로] → 앞다리 운동 명령
                                  ↑                          ↓
                            보상 조절 신호 ←──── 타구 결과(접촉/방향/비거리)
```

모든 물리량은 파리 실물 단위(mm·g·μN). 모든 신호는 하나의 타임라인에
기록되어 4분할 뷰어로 재생된다.

## 단계와 게이트

각 Phase는 **게이트**를 통과해야 다음으로 넘어간다. 게이트는 실행 전에
기준을 고정하고, 결과가 나쁘다고 기준을 완화하지 않는다.

### Phase 0 — 보존하고 정리 *(현재 단계)*

`archive/human-scale-v0` 태그로 이전 상태를 고정한 뒤, 작업 트리에서는
`flyohtani/` 단일 패키지만 남긴다. 살리는 것: NeuroMechFly STL 메시(+라이선스),
`sense/`로 이관한 시각 모듈, 라이선스·출처 문서, 이 계획, 선행 발견 요약.

### Phase 1 — 몸: "파리가 배트를 휘두를 수 있는가"

`units.py`(mm·g·μN 단일 정의) → flygym 1.2.1 원본 MJCF에서 앞다리 2개
(각 7DOF: Coxa_yaw, Coxa, Coxa_roll, Femur, Femur_roll, Tibia, Tarsus1) +
지지된 Thorax + Head 추출 → 양 앞다리 tarsus에 배트 부착.
Tarsus2–5는 원본대로 수동 스프링으로 둔다(원본조차 능동 구동하지 않는다).

관절 범위는 원본 MJCF에 하드 리밋이 **없다**. `pose_stretch`/`pose_tripod`
사이를 참조 범위로 삼되, 그 범위를 벗어나는 설정은 "파생 공학 모델"로
표기한다.

> **게이트 G1 — 무공 스윙 스윕**
> 도구 질량 × 길이 격자에서 앞다리 위치제어가 낼 수 있는 **배트 끝 최대
> 속도**를 실측하고, 구동 전용 dt 수렴을 확인한다. 이 한 숫자가 공 질량·
> 투구 속도·인필드 거리를 전부 역으로 결정한다.
> 실패 시 경로: 도구 경량화 → 단축 → 그래도 안 되면 gear 증폭을 하되
> **"파생 모델"로 명시 기록**한다. 조용히 힘을 키우지 않는다.

### Phase 2 — 세계와 접촉

G1이 준 배트 속도에서 도달 가능한 거리로 홈플레이트·파울라인·내야 경계를
역산 배치(D21). 투구 런처(릴리스 위치·속도·지터). 초기엔 크고 느리고 대비가
뚜렷한 공. 공기저항 활성화(D23).

> **게이트 G2 — 접촉 수용 검증**
> [선행 발견](records/PRIOR-FINDINGS.md) §2의 사전 등록 수용치를 **그대로**
> 새 스케일에서 재실행한다: 반발계수 0.3~0.7, 관통 ≤30%×min(반지름),
> dt 수렴 오차 ≤2%, 에너지 잔차 ≤5%, 자유 배트 운동량 보존 ≤1%.
> solref/solimp 후보 비교는 선행 P2가 남긴 방식대로 진행하되 **비거리
> 최대화로 재료를 고르지 않는다.**
> 통과하지 못하면 학습 개시를 계속 보류한다.

### Phase 3 — 눈

`sense/eye_camera.py`를 새 rig의 Head body에 재부착. 단안 유지(루밍 검출은
단안으로 성립하며, 스테레오는 다른 감각 조건이므로 섞지 않는다).
**해상도/FOV를 새 스케일에서 재측정한다** — 선행 V1의 검출률 수치는 옛
스케일의 픽셀 크기에서 나온 것이라 그대로 쓸 수 없다.

신규: 망막 → 스파이크 인코딩(ON/OFF 대비 채널 + 시간 미분). Phase 4의 입력.
`VisionObservation`의 자기감각 필드는 새 앞다리 관절로 교체한다.
금지 채널(정답 공 위치/속도/도착시각/코스/트리거) AST 검사는 유지한다.

### Phase 4 — 뇌

> **게이트 G4 — 데이터 접근 확인 (Phase 1~3과 병행, 최우선)**

> `RESEARCH_SOURCES.md`에 기록한다. 막히면 D19를 재논의한다.

커넥톰 로더(body ID · type · 시냅스 접점 수 C_ij, C→모델 연결 P 변환식
명시) → LIF 시뮬레이터(NumPy, dt 1ms) → 운동 디코딩(하류 발화 → 앞다리

## 단독 진행의 보완 장치 (D25)

D01 시절에는 계획·검토와 구현이 다른 주체에 있었고, 그 분리가 실제로 오류를
잡았다 — v1의 메시 반입에서 파일 수(43 vs 45)·좌표계 버그·비균일 스케일 세
가지는 독립 검토가 찾아낸 것이다(그 기록은
`flyohtani/assets/mesh_neuromechfly/PROVENANCE.json`에 그대로 보존한다).

이제 그 분리가 없다. **"더 조심하겠다"는 다짐은 장치가 아니므로**, 검토가
하던 일을 자기 검사 가능한 형태로 대체한다:

1. **수용 기준은 실행 전에 고정한다.** 결과를 본 뒤 기준을 만들지 않는다.
   G1의 사전 등록 격자, G2가 재사용할 [접촉 수용치](records/PRIOR-FINDINGS.md)
   §2가 그 형태다.
2. **한 숫자를 믿기 전에 그 숫자를 흔든다.** dt 수렴, 적분기 교차검증,
   솔버 설정 민감도. v1의 철회된 결론과 G1의 `boundmass` 8.3% 차이는 모두
   이 검사가 아니었으면 놓쳤을 것이다.
3. **설계 결정과 측정을 기록에서 분리한다.** "이렇게 정했다(공학적 선택)"와
   "이렇게 나왔다(측정)"를 같은 문장에 쓰지 않는다.
4. **모델이 원본에서 왔다는 것을 테스트가 강제한다.** 사람이 다시 확인하지
   않아도 되도록, 원본 파일과의 대조를 회귀 테스트로 고정한다.
5. **불리한 결과를 먼저 쓴다.** 통과 판정 옆에 그 판정이 무엇을 보장하지
   *않는지*를 같이 적는다.

## 작업 원칙

- 미결정 연구 선택을 임의의 수치로 채우지 않는다. 의존하는 작업만 대기하고
  독립 작업을 계속한다.
- 실행 결과는 `records/VALIDATION_LOG.md`, 상태 변화는 `records/STATUS.md`에
  남긴다. **테스트 통과와 연구 가설의 검증을 구분한다.**
- 실패·무효 결과를 보존한다. 결과가 나쁘다는 이유로 시드를 제외하거나 과거
  실행을 삭제하지 않는다.
- 외부 코드·데이터의 출처·버전·체크섬·라이선스를 `RESEARCH_SOURCES.md`와
  데이터 manifest에 기록한다.
- 규칙·시드·판정 기준을 바꾸면 날짜·변경 전후·이유·이미 열람한 결과 범위·
  새 버전을 남긴다.
